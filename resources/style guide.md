

# GAVIN  STYLE FORMAT

### Code Structure

- **Variables**: Use lowercase words separated by underscores. For example: my_variable.
- **Functions**: Use lowercase words separated by underscores. For example: my_function.
- **Classes**: Use CamelCase with the first letter of each word capitalized. For example: MyClass.
In addition to the above, there are a few more conventions to keep in mind:
- **Interfaces**: User Identifier prefix capital 'i'  followed by CamelCase with the first letter of each word capitalized. example: IMyInterface.
- **Private variables and functions**: Prefix the name with an underscore. For example: _my_private_variable.
- **Protected variables and functions**: Prefix the name with two underscores. For example: __my_protected_variable.
- **Constants**: Use all uppercase words separated by underscores. For example: MY_CONSTANT.
- **Varaible Constants**: use the prefix VAR_ and then all uppsercase words separated by underscrores. example: VAR_NAMES. varaible constants are varaibles that GAVIN can change
- **getters and setters methods**: user camelcase formatting, the key word set of get are not capitalized and the rest of the words use title case: example setBridgeLength

### Directory structure

- **Modules**: camelcase, without underscores separating words (e.g. myModule.py)  (file)
- **Packages**: lowercase, with no underscores (e.g. mypackage) (folder)
